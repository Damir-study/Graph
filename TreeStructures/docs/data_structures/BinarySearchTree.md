# Системный анализ бинарного дерева поиска

## 1. Какую проблему решает структура?

Нужно хранить изменяемый набор значений и быстро искать элементы, сохраняя возможность получить их в порядке возрастания. Неупорядоченный массив требует перебора; отсортированный массив позволяет быстро искать, но вставка обычно требует сдвигов.

Дерево поиска использует порядок значений для выбора направления движения.

Например, в справочнике сотрудников нужно находить запись по номеру, добавлять новых сотрудников и получать записи по порядку номеров. Дерево позволяет совместить эти действия: порядок хранится в самой структуре, поэтому для каждого вывода не требуется заново сортировать весь набор.

## 2. Что она собой представляет?

Это бинарное дерево с упорядоченными поддеревьями.

```text
        8
       / \
      3   10
     / \    \
    1   6    14
```

Узлы содержат значения, а связи определяют путь поиска. Для определённости далее рассматривается вариант с уникальными значениями.

Из каждого узла можно перейти только к его детям. Высота показывает, сколько уровней придётся пройти на самом длинном пути. Одни и те же значения могут образовать разные деревья: форма зависит от порядка вставки, хотя результат упорядоченного обхода будет одинаковым.

## 3. Какие правила всегда должны выполняться?

Для каждого узла все значения левого поддерева меньше его значения, все значения правого — больше. Правило действует на всех потомков, а не только непосредственных детей.

Сравнение должно задавать согласованный порядок. Если порядок значений меняется без перестройки дерева, поиск может перестать находить существующие элементы.

Например, если корень равен 8, значение 9 не может находиться нигде в его левом поддереве, даже если оно оказалось правым ребёнком узла 3. Отношение с непосредственным родителем могло бы выполняться, но ограничение предка 8 уже нарушено. Именно поэтому правило проверяют для целых поддеревьев.

## 4. Что пользователь может с ней делать?

Добавлять, искать и удалять значения; проверять наличие; получать минимум, максимум; выполнять упорядоченный обход. 

Поиск и обход читают дерево. Вставка и удаление изменяют его состав и могут менять форму.

Поиск возвращает конкретную запись либо сообщает, что её нет.

## 5. Как выполняются основные операции?

Поиск 6 в примере: `6 < 8` — идём влево; `6 > 3` — вправо; найден узел 6. При вставке аналогичный путь заканчивается свободной позицией.

При удалении лист убирают. Узел с одним ребёнком заменяют ребёнком. Для узла с двумя детьми можно перенести на его место минимум правого поддерева, удалив его из прежней позиции.

ЛКП посещает левое поддерево, узел и правое поддерево, выдавая отсортированные значения.

Рассмотрим удаление корня 8 на рисунке. Минимум правого поддерева равен 10, поэтому он может занять место 8. Слева останутся значения 1, 3, 6, а справа — 14. Если у переносимого узла есть правый ребёнок, он занимает его прежнее место: иначе часть данных будет потеряна.

## 6. Почему алгоритмы корректны?

Если искомое значение меньше текущего, оно не может находиться справа: все значения там больше текущего. Поэтому исключение правой ветки безопасно.

Вставка на найденное место сохраняет ограничения всех предков. При удалении минимум правого поддерева подходит для замены: он больше всех значений слева и не больше остальных значений справа.

## 7. Сколько ресурсов требуется?

Поиск, вставка, удаление и поиск экстремума занимают `O(h)`. При высоте `O(log n)` это логарифмическое время; в худшем случае высота равна `O(n)`.

Для случайной перестановки уникальных вставляемых значений ожидаемая высота — `O(log n)`; без предположений о входных данных эта оценка не гарантируется. Полный обход — `O(n)`, хранение — `O(n)`, стек рекурсивного обхода — `O(h)`.

Логарифмическое время получается из небольшой высоты: при удачной форме каждый переход оставляет примерно половину кандидатов. В цепочке один переход исключает только один узел. 

## 8. Какие случаи требуют отдельного решения?

Отсутствующий элемент, пустое дерево, удаление корня и узел с двумя детьми. Повторы могут запрещаться, учитываться счётчиком или размещаться по согласованному правилу. Это правило должно учитываться всеми операциями.

Пустое дерево не имеет минимума, поэтому интерфейс должен сообщить об этом, а первая вставка должна установить корень. При удалении корня нужно обновить сам корень, поскольку родителя нет. Узел с двумя детьми требует замены, сохраняющей обе ветви. Для отсутствующего значения заранее определяют, будет ли ошибка или отсутствие изменений.

## 9. Как структура представляется в памяти?

Обычно каждый узел содержит значение и указатели на детей. Вставка не требует сдвигать остальные значения, но выделение отдельных узлов и переходы по указателям имеют свою стоимость. Иногда дополнительно хранят родителя или размер поддерева.

Указатели позволяют менять связи, не сдвигая весь набор, как в массиве. Однако узлы могут оказаться в разных участках памяти, поэтому переходы между ними часто менее удобны для процессора, чем последовательное чтение массива. Если узел удаляется, ссылки на него перестают быть пригодными для использования.

## 10. Каковы преимущества и ограничения?

Сохраняет порядок и поддерживает как точечный поиск, так и диапазоны. Главный недостаток — зависимость от формы: вставки `1, 2, 3, 4, 5` создают цепочку правых детей. Тогда поиск становится линейным, а заполнение дерева занимает `O(n²)`.

Если данные приходят почти отсортированными, плохая форма возникает не как редкое исключение, а как ожидаемый результат обычной вставки. Поэтому выбор BST без балансировки оправдан, когда допустимы такие риски или форма контролируется отдельно. Кроме того, поиск требует согласованного сравнения: для объектов нужно определить, по какому полю они упорядочены.

## 11. Какие есть альтернативы?

AVL гарантирует малую высоту ценой балансировки. Хеш-таблица обычно удобнее для точного поиска без требований к порядку. Отсортированный массив хорош при редких изменениях. Куча подходит для выбора экстремума, но не обеспечивает такой же поиск по ветке.

Выбор зависит от операций, которые выполняются чаще. Для часто меняющегося набора с диапазонами подходит сбалансированное дерево. Если набор почти не меняется, отсортированный массив сочетает двоичный поиск с компактным хранением. Если порядок не нужен, словарь на хеш-таблице может дать более быстрый точный поиск в среднем.
